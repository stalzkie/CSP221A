The build_inventory function goes through each raw row and tries to turn it into a Product using from_dict. Since I put the validation inside the price and quantity setters, any bad value (like a negative price or negative quantity) automatically raises InvalidPriceError or InvalidQuantityError when the Product is being created. I wrapped this in a try/except InventoryError, which catches both exceptions since they share that same base class. This way, if one row is bad, it doesn't crash the whole program, it just gets added to the failures list along with the original row data and the error message, while the good rows go into products like normal.

For what counts as a "failure," I decided it's only when the row fails the actual validation rules — so a price that's 0 or negative, or a quantity that's negative. I made sure a quantity of exactly 0 still counts as valid, since that just means the item is out of stock, not that the data itself is wrong.
