A row that I think counts as a failure is dropped rather than fixed. When it's missing information required for the audit, for example in the R04's rating was "not_rated", which cannot be converted into a number so there is no way to categorize, so we have to drop it. A duplicate respondent like R01 is also dropped, since keeping both would double count one person. Messy-but-fixable issues like extra spaces or inconsistent casing in an ID don't lose any information, these can be corrected with a simple .strip() and .lower()/.upper() and the row is kept.
